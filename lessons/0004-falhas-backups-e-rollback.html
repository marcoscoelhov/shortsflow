Uma falha de deploy não deve virar perda de código ou estado

A recuperação tem camadas distintas: Git para código, release anterior para aplicação, SQLite verificado para estado e cofre cifrado para secrets.

Quatro proteções

ProteçãoGuardaRetenção
Branches/snapshotsEstados local e VPS reconciliadosBundles e branches de recuperação
ReleasesCódigo e dependências implantadosAtivo + 3 anteriores
Backup SQLiteJobs e metadados do ambiente7 diários, 4 semanais, 3 predeploy
Cofre cifradoProvider keys e configuração secretaSeparada do banco e do Git

O que o deploy faz

  1. Confirma capacidade e se o SHA pertence ao branch permitido.
  2. Prepara o release antes de tocar no ativo.
  3. Drena novos jobs e espera o atual.
  4. Cria backup consistente pelo mecanismo do SQLite.
  5. Troca current, reinicia e verifica ambiente + SHA.
  6. Em falha, restaura link e SHA anteriores e reinicia.

Migrações de banco precisam ser compatíveis com os quatro releases retidos. Se não forem, rollback inclui restaurar o predeploy correspondente.
